# Проверка синхронизации через iCloud

Статус: **не пройдена.** Код CloudKit/CKShare есть, но на двух физических iPhone с разными Apple ID он не запускался. До прохождения этой проверки семейный режим не считается рабочим, и новые функции интерфейса не начинаются.

## Реквизиты

- Team ID: `AKH3FW2JK6` (платный Apple Developer Program).
- Bundle ID: `dev.korevagit.folki`.
- Контейнер: `iCloud.dev.korevagit.folki.budget` — новый и пустой. Прежний `iCloud.dev.korevagit.folki` не используется, данные из него не переносятся.
- Схема Xcode: `Folki-iCloud`, конфигурация `Cloud`, development environment.
- Локальные данные: `Application Support/Folki/v1`. Хранилища предрелизных схем и каталог `FolkiBudgetV1` приложение не читает.
- Схема CloudKit: перед проверкой сбросить development-окружение контейнера в CloudKit Console (Reset Development Environment), чтобы в нём не остались типы записей предрелизных схем.

## Подготовка

1. В Xcode открыть `Folki-iCloud` → Signing & Capabilities → iCloud и убедиться, что контейнер `iCloud.dev.korevagit.folki.budget` создан и отмечен. При автоматической подписи Xcode регистрирует его сам.
2. Установить одну и ту же сборку `Folki-iCloud` на оба iPhone. Телефоны должны быть под разными Apple ID, iCloud Drive включён.
3. На первом телефоне создать личный и семейный планы. На втором — только личный: принятие приглашения не объединяет два семейных бюджета.
4. Один раз запустить сборку на первом телефоне с аргументом `-FolkiInitializeCloudSchema YES` (Edit Scheme → Run → Arguments), потом убрать аргумент. Так в схему попадут все типы записей, включая `CD_Envelope`, даже если экран конвертов ещё не готов.
5. После первого запуска открыть CloudKit Console → development → схема контейнера и убедиться, что появились записи `CD_Household`, `CD_Transaction` и остальные.

После каждого шага сверять UUID операций и оба финансовых снимка, а не только текст на экране. Успешный экспорт в iCloud ещё не означает доставку на второй телефон.

## Известные ограничения

- Взнос записывается одной сохранкой в два хранилища: личная сторона — в private store автора, семейная — в shared store. Локально обе стороны появляются вместе. На других устройствах видна только семейная сторона; это ожидаемо.
- Лимит в пять участников — клиентское правило, а не серверное ограничение CloudKit.
- Перед TestFlight схему нужно развернуть в production через CloudKit Console.

Основа реализации: [Sharing Core Data objects between iCloud users](https://developer.apple.com/documentation/coredata/sharing-core-data-objects-between-icloud-users).
