# FolkiDuoCore

Чистая финансовая логика: Foundation, без SwiftUI, Core Data и CloudKit. Проверяется через `swift test --package-path Core` на Mac с Swift 6.2+.

## Вход и результат

`HouseholdSnapshot` содержит начальные деньги и резервы на начало периода, свободный месячный план и операции. `DailyBudgetCalculator.calculate(_:asOf:)` получает явное время расчёта; календарь и часовой пояс берутся из `BudgetPeriod`.

Операции до начала периода и позже момента расчёта не входят в результат. Исходные записи не меняются; дубли UUID отклоняются. Для операции с одинаковым временем порядок стабилизируется UUID. Переводы между резервами должны иметь корректные причинные даты; конфликты совместных записей разрешает будущий слой хранения.

`DailyBudgetSnapshot` — единственный источник дневного остатка, месячного остатка, обеих дуг и прогноза. `PurchaseImpactCalculator` принимает этот снимок и сумму, не создаёт расход и не меняет данные.

## Деньги и округление

Money хранит Int64 минимальных единиц и валюту с явной точностью. Ввод проверяется целиком; `1 234,50` и `1234.50` допустимы, `1.234` для RUB и `123abc` отклоняются. Все сложения и вычитания проверяют переполнение. Double используется только для визуальной доли кольца.

`DailyAllocation` сохраняет каждую минимальную единицу. Первые `extraUnitDays` получают на одну единицу больше `standardAmount`. Поэтому следующий день для 37 550 ₽ / 14 — 2 682,15 ₽, остальные дни могут получить 2 682,14 ₽. Краткое «≈2 682 ₽» в ранних макетах округляло до рублей.

## Резервы и доход

- Покупка из `.flexible` уменьшает свободный остаток и сегодняшний доступный бюджет.
- Оплата `.reserve(id)` уменьшает и деньги, и зарезервированную сумму; свободный остаток второй раз не меняется.
- `reserveAllocation` и `reserveRelease` меняют план, не создавая трат. Остаток резерва не может стать отрицательным.
- Доход по умолчанию `.unallocated`: он не повышает ориентир без явного решения. Для прямого включения дохода в план нужно явно выбрать `.flexible`.
- Возврат учитывается датой операции в заданном периоде. Контроль связи с исходной покупкой и допустимой общей суммы возврата относится к будущему сервису записи; текущий калькулятор работает с уже подтверждённым снимком.
- Отдельный GoalContribution не списывает деньги повторно. Будущий сервис цели создаёт соответствующий перевод резерва атомарно с записью вклада.

Дневной ориентир не сдвигается от сегодняшних покупок. Явные поступления в план и изменения резерва корректируют его базу, потому что меняют сам план. На последнем дне прогноз отсутствует; отрицательный свободный бюджет остаётся дефицитом, а не превращается в разрешённую сумму траты.
